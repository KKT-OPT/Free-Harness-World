# 有状态算法验证

本 Skill 经用户明确授权，在验证通过后于2026-10-28晋升为reviewed；与代码审查、实现和性能Skill按职责协作，不修改项目验收标准。

## 入口与输入

先按根目录入口读取项目约束与当前工作流，再读取项目权威架构、数据/标签规范、评价契约和稳定测试命令。
必须确认：允许修改的算法边界、在线输入/状态接口、参考来源、主指标、数据划分、冻结配置与评价器身份、用户审核范围。
缺少可比基线时只完成流程验证，不能宣称效果提升或正式验收。

仅需普通审查时使用 `harness/skills/reviewed/code-review/SKILL.md`；批准后的修改使用
`harness/skills/reviewed/code-implementation/SKILL.md`；性能根因分析另交
`harness/skills/reviewed/algorithm-performance-analysis/SKILL.md`。

## 执行流程

1. **拆开职责。** 生成器知道计划，用于生成轨迹与真值；独立标注器可看完整数据，用于生成参考；在线算法只能看本轮及传入历史。
   测试 runner 负责回放和计算指标。禁止把待测算法实现、阈值、生命周期参数或预测结果喂给独立标注器以制造一致性。
   可以共享经批准的术语/标签格式，但不因此共享识别逻辑。
2. **验证真实调用链。** 生产算法消费治理/融合后的数据时，真实与仿真 raw 都经同一必要主链。
   复用项目稳定回放能力，不另造省略治理、时间轴或状态更新的测试入口。
   按接收时间推进，保留事件时间；不能要求 raw 时间恰好等于算法输出网格时间。
3. **守住因果边界。** 每轮仅回传上一轮实际状态。调用后再解锁参考；参考不得进入请求、配置或历史状态。
   测试追加未来输入后，既有前缀输出不得被回写。重复尾点、无新增点、补点、失败/恢复、关闭/重开按项目契约断言，
   不把重复调用自动当作新增证据或固定认定为主链缺陷。
4. **选对评价单元。** 按批准契约区分逐点、区间/事件、模式发生序列、时效和 UNKNOWN。
   离线物理边界与在线确认时间可不同；序列数量/顺序正确不等于边界/延迟合格，低 UNKNOWN 也不等于高 F1。
   一对一匹配、防重复计分、零命中和全空边界必须有手算夹具。不要用降低分母或改标签掩盖失败。
5. **冻结对照。** 记录数据家族、参考审核版本、配置内容身份、评价器和代码身份、完整/partial范围。
   参数隔离验证与正式默认分开；用户批准前不晋升参数/版本。development不能改名充当独立 holdout。
6. **逐层归因。** 分开检查输入/融合质量、参考标签、识别逻辑、阈值/窗口、测试适配和指标公式。
   参考严重冲突时按独立几何/业务证据复核，不把人工裁决当绝对真值，也不以算法预测反改参考。
   联合代表性来源/场景，分列总体净收益与局部代价；是否接受退化由用户决策，不能自设“每包零退化”。
7. **验证状态和契约。** 为持久化字段说明下一轮消费者；摘要、版本、展示字段不能因方便就复制进历史。
   减容要覆盖窗口重叠、活跃候选、事件组合和长时输入，比较逐轮输出/状态演进；不能只截尾以达到字节目标。
   可选输出关闭不应改变识别结果；性能优化不能删除必要证据或异常守护。
8. **交付并交回审核。** 工作流保存命令、计数/资格、指标、范围覆盖、残余风险、批准状态。
   缺测、合理不适用、无法计算、计算失败与数值零分开。有限开发接收不等于独立泛化、部署或全项目验收。

## 验证与失败处理

验收至少覆盖：无标签泄露、跨轮因果/重复输入、手算指标边界、冻结身份、正式/隔离配置区分、
参考冲突处置、局部代价和未测项。只有用户要求的范围全部有证据时才请求该范围验收。

若可执行入口失败，先用 simulation-failure-triage 区分环境、编译、数据、断言和算法问题；
环境失败不报算法不合格。基线或参考无效则停止效果结论，保留缺口和修复动作；不能通过屏蔽失败继续算漂亮分数。
